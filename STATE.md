## Retrieval SQL

```sql
sqlite3 -readonly ~/.local/share/opencode/opencode.db "
SELECT id, title, model, cost,
       tokens_input, tokens_output, tokens_reasoning,
       tokens_cache_read, tokens_cache_write,
       datetime(time_created/1000,'unixepoch') AS created_utc,
       datetime(time_updated/1000,'unixepoch') AS updated_utc
FROM session
WHERE id = 'ses_e060021a6ffePSeL2sNxw268dB';"
```

The session id was located in `~/.local/share/opencode/log/opencode.log` (`session.id=ses_...`).

## Caveats

- Token totals are a point-in-time database snapshot; the live session keeps counting until the conversation ends.
- The reported wall-clock time is the session row's creation-to-snapshot interval, not a hand-timed stopwatch.
- Cache reads are counted raw, so the total is much larger than the "fresh" input + output cost.
- Costs are provider-reported at the snapshot and can be adjusted by the provider later.
